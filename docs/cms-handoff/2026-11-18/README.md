# Передача CMS-контенту Vortex · 18.11.2026

Почати з [уточнень до API](API-уточнення.md). Вони доповнюють [початкове ТЗ](reference/CMS-original-spec.md), визначають прогалини контракту й розподіл робіт PHP / Node / React.

Пакет містить поточний контент **українською, чеською, словацькою, англійською та польською** (`ua`, `cz`, `sk`, `en`, `pl`). Це локальний знімок і запропонований формат імпорту. Реальний API CMS ще не перевірений; імпорт або публікація цим пакетом не виконуються.

## Що перенесено

Для кожної мови збережено всі старі корені `homepage`, `FAQ`, `videos`, `contacts`, `settings`, `stats`, `ui`, `car_service`. В `ui` 217 ключів з урахуванням фактичного пріоритету поточних локалей. Початкові значення залишилися в `raw-source/server/data/vortex.json` і `raw-source/client/src/locales/`.

Додано схеми імпорту для автошроту, TecDoc, сайтів, layout, SEO, повних інтеграцій і політики. Кожна мова містить:

- 7 карток і 7 сторінок інтеграцій, усі 19 ілюстрацій та партнерські посилання без зміни query-параметрів;
- 14 розділів політики з повним HTML, посиланнями й датою редакції `2026-11-16`;
- 3 тарифи сайтів і 27 послуг з явними `included`, включенням 10/20/27 послуг та відмінними підписами для окремих тарифів;
- 15 постачальників, тексти Vortex Sync, 6 FAQ, 4 відео, 4 контакти, 6 блоків СТО й усі інші наявні розділи;
- прихований `homepage.vortex_pricing_section`: `visible:false`, `plans:[]` і переклади підписів періоду оплати.

Видалений `why_vortex_showcase_section` відсутній і не повинен відновитися при імпорті.

## Порядок використання

1. Погодити доповнення контракту з основного документа. Поля `integration_pages`, `privacy_policy`, `seo.integrations`, `seo.privacy_policy`, пакети й додаткові поля layout/TecDoc/тарифів — **пропозиції**, їх підтримку PHP API ще потрібно підтвердити.
2. Імпортувати всі п’ять мов однією ревізією. Не змінювати стабільні ID, slug, юридичні реквізити, посилання й шаблонні `{number}` / `{year}`.
3. Завантажити медіа за manifest. Якщо CMS видаватиме абсолютні URL, узгоджено замінити всі відповідні посилання та зберегти alt. Порожні alt у декоративних зображень не заповнювати автоматично.
4. Окремо розглянути прогалини нижче. Після імпорту повернути реальний `GET /content`, `/content/media`, заголовки кешу та preview fixtures для підключення Node/React.
5. Пакети Vortex залишити прихованими й порожніми. Публікація тарифів потребує погодженого наповнення від відповідальної особи.

`content.json` не слід просто підставляти замість локального файла й вважати CMS підключеною: поточні компоненти ще не читають усі нові поля. Імпорт у CMS та адаптер сайту — окремі роботи, описані в уточненнях.

## Прогалини, які знімок зберігає чесно

- У відгуках виявлено **40 значень Lorem ipsum** сумарно за п’ятьма мовами; їхні шляхи є в `export-report.json`. Контент не переписувався й не вигадувався.
- Галерея `/websites` має три порожні зображення та порожні URL прикладів; поточний glob також не знаходить `overview`. Реальний `site_2.png` використовується на головній і входить до архіву. Його не призначено автоматично прикладом тарифу.
- Ціни сайтів 0/300/500 USD, примітка про додаткові $10 і TecDoc 25 EUR/місяць узяті з поточного коду. Це не нове погодження комерційних умов. Калькулятор зберігає чинний символ валюти `$`.
- Пакетів CRM ще немає. Нуль у кількості планів є очікуваним станом.
- Реальних статей CMS локально немає. Demo-файл збережено окремо; майбутнє `seo.blog.indexing:"index"` не скасовує `noindex,follow` для demo.
- Медіафайли перевірені локально; відсутніх файлів за зібраними посиланнями немає. WebP/thumb не створювалися. Manifest також містить ресурси клієнтського оформлення й demo-обкладинки; не всі вони потребують редакторських полів CMS.

## Відтворення та контроль

У поточному репозиторії з установленими залежностями клієнта й Python Pillow:

```sh
node scripts/export-cms-content.cjs
```

Скрипти є в `raw-source/scripts/`. Генератор оновлює JSON, медіа й raw-source для цього датованого знімка; він не створює API, не виконує імпорт і не публікує контент. Документ, копії довідкових ТЗ, `validation-report.json`, контрольні суми й ZIP завершуються окремо після перевірки.

Після розпакування перейти до кореня пакета й перевірити контрольні суми:

```sh
shasum -a 256 -c MANIFEST.sha256
```

У пакеті немає `.env`, даних доступу до адмінки, `users.json`, preview-токенів або реальних заявок.
